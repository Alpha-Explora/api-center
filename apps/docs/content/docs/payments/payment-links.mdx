# Payment Links and QR Ph

## Payment links

Create a hosted PayMongo payment link with a PHP amount and a stable merchant reference:

```http
POST /api/v1/payments/payment-links
Idempotency-Key: order-link-1001
```

```json
{
  "referenceId": "ORDER-1001",
  "amount": { "amountMinor": 25000, "currency": "PHP" },
  "description": "Order 1001"
}
```

The response includes `paymentLinkId` and the hosted `url`. Use `GET /api/v1/payments/payment-links` to list links created by the calling project, or `GET /api/v1/payments/payment-links/{paymentLinkId}` to retrieve one. A link can be archived or restored with `PATCH` and `{ "archive": true }` or `{ "archive": false }`; each mutation requires its own `Idempotency-Key`.

Payment links are scoped to the project that created them. A `link.payment.paid` PayMongo webhook updates the recorded link status to `paid`. The link's `active` or archived state describes availability, not whether a payment has completed.

## QR Ph

Create a payment intent, QR Ph payment method, and attachment in one APICenter call:

```http
POST /api/v1/payments/intents/qrph
Idempotency-Key: order-qr-1002
```

```json
{
  "referenceId": "ORDER-1002",
  "amount": { "amountMinor": 25000, "currency": "PHP" },
  "expirySeconds": 1800
}
```

The response contains `paymentIntentId`, `qrCodeImageUrl`, `expirySeconds`, and status. `expirySeconds` is optional; PayMongo defaults to 1800 seconds. When supplied, it must be an integer from 60 through 9000 seconds. Render the returned image URL as the QR code.

`awaiting_next_action` means the QR code is ready for the customer. It does not mean the payment is complete. Confirm payment using the `payment.paid` webhook or retrieve the intent with `GET /api/v1/payments/intents/{paymentIntentId}`.
