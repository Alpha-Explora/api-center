---
title: "Payment Intents API"
description: "Create, retrieve, confirm, and cancel payment intents through the public payment API."
---

Payment intents expose a provider-neutral way to create, attach a client-created payment method, and track a payment. Payment-method tokenization stays client-side; do not send card numbers or other sensitive payment data to your backend. The short-lived `clientKey` returned for an intent is scoped to that intent and is not a secret API key.

For a Node.js backend, use `api.payments.intents.create(...)` or `api.payments.intents.createQrPh(...)` from the [APICenter SDK](/guides/sdk-usage). The REST examples below are for other runtimes.

## Create a payment intent

- **Endpoint**: `POST /api/v1/payments/intents`
- **Required scope**: `payments:intents:write` or a broader payment write scope
- **Required header**: `Idempotency-Key`

```bash
curl -X POST https://api-center.itsandbox.site/api/v1/payments/intents \
  -H "Authorization: Bearer $PAYMENT_API_KEY" \
  -H "Idempotency-Key: intent-create-1002" \
  -H "Content-Type: application/json" \
  -d '{
    "referenceId": "INTENT-2026-001",
    "amount": {
      "amountMinor": 125000,
      "currency": "PHP"
    }
  }'
```

A successful response includes a `paymentIntentId`, normalized `status`, `amount`, and `aggregateVersion`. It also includes `clientKey` when PayMongo returns one; pass that key back when attaching a payment method.

## Retrieve, confirm, or cancel

- **Retrieve**: `GET /api/v1/payments/intents/{paymentIntentId}` with `payments:intents:read`.
- **Confirm**: `POST /api/v1/payments/intents/{paymentIntentId}/confirm` with `payments:intents:write`.
- **Cancel**: `POST /api/v1/payments/intents/{paymentIntentId}/cancel` with `payments:intents:write`.

Confirm and cancel require their own `Idempotency-Key` values. Confirmation accepts a client-created `paymentMethodId`, the intent's `clientKey`, and a `returnUrl`:

```json
{
  "paymentMethodId": "pm_example",
  "clientKey": "pi_example_client_key",
  "returnUrl": "https://merchant.example/payments/complete"
}
```

For the SDK, pass the same fields as the second argument to `api.payments.intents.confirm(paymentIntentId, input, options)`. When customer authentication is needed, the response includes `nextAction.redirectUrl`; send the customer there. The intent's `GET` response also returns the current `nextAction` if the original confirmation response was lost. A return to `returnUrl` is not proof of payment; retrieve the intent or verify the payment webhook before fulfilling an order.
