# Consumer Runbook

APICenter consumers call the provider-neutral payment API with the published
TypeScript SDK. A consumer owns its business records and receives normalized
payment lifecycle events; APICenter owns provider credentials, idempotency,
event publication, and the payment resource state.

## Before Production

- Register the consumer service and environment in APICenter Management.
- Request only `payments:read` or `payments:read,payments:write`.
- Store `APICENTER_API_KEY` in the backend secret manager.
- Provision the Pub/Sub push subscription and Cloud Run OIDC identity.
- Make event handling idempotent by `eventId` and monotonic by
  `aggregateVersion`.

## Payment Request

```ts
const checkout = await client.payments.createCheckout(
  {
    referenceId: order.id,
    amount: { amountMinor: order.totalMinor, currency: "PHP" },
    successUrl: "https://orders.example/payment/success",
    cancelUrl: "https://orders.example/payment/cancel",
  },
  { headers: { "Idempotency-Key": `checkout:${order.id}` } },
);
```

Treat the checkout as pending until `payment.checkout.paid` is projected. Do not
trust a redirect alone to grant access.

## Event Handling

Verify the Cloud Run OIDC token, validate the canonical event envelope, discard
an already-seen `eventId`, and ignore an event whose aggregate version is not
newer than the stored version. Never expect PayMongo fields in `data`; provider
details are intentionally not part of the public contract.

## Failure And Rollback

Retry transient API failures with the same idempotency key. For a delivery
failure, inspect the dead-letter subscription and replay the same event after
the consumer is corrected. If APICenter announces a payment cutover rollback,
continue serving existing local state and pause new payment commands; do not
call PayMongo directly.

See the operator [payment platform runbook](/operations/payment-platform-runbook)
and [cutover checklist](/operations/payment-platform-cutover-checklist) for
release and incident procedures.
