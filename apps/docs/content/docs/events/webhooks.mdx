---
title: "Payment webhooks"
description: "Receive signed payment events at an HTTPS endpoint and verify them."
---

APICenter can POST your application's payment events, such as `payment.checkout.paid`, to any public HTTPS URL on your backend. Each delivery is signed with a secret only you and APICenter know, and APICenter retries until your endpoint answers with a 2xx status. Your backend can run anywhere and be written in any language.

APICenter delivers payment events to your application as signed HTTPS webhooks.

## Set up an endpoint

1. Add an HTTPS route to your backend, for example `POST /apicenter/events`. It must be publicly reachable; private and internal addresses are refused.
2. In Management, open the project's **Webhooks** section in each environment (test and live) and add a webhook for your application with that URL, or ask your APICenter operator to. Payments must be enabled in the environment, and each application has one active destination.
3. Store the signing secret (`whsec_…`) shown when the destination is created. It is shown once. Keep it in your backend's secret store, never in a browser or mobile app.

## Verify every delivery

Each request carries three headers, following the [Standard Webhooks](https://www.standardwebhooks.com/) format:

| Header | Meaning |
| :--- | :--- |
| `webhook-id` | The event's `eventId`. The same event always has the same ID, including retries. |
| `webhook-timestamp` | Seconds since the Unix epoch when this attempt was signed. |
| `webhook-signature` | One or more `v1,<base64 HMAC-SHA256>` values, separated by spaces. |

With the SDK, pass the **raw** request body (before JSON parsing), the headers and your secret:

```ts
import express from 'express';
import { verifyWebhook, ApiCenterWebhookError } from '@alpha-explora/apicenter-sdk';

app.post('/apicenter/events', express.raw({ type: 'application/json' }), async (req, res) => {
  let event;
  try {
    event = await verifyWebhook(req.body, req.headers, process.env.APICENTER_WEBHOOK_SECRET!);
  } catch (error) {
    if (error instanceof ApiCenterWebhookError) return res.status(400).end();
    throw error;
  }
  await recordOnce(event); // see "Process each event once"
  res.status(204).end();
});
```

Without the SDK, any Standard Webhooks library works. To verify by hand: decode the secret after `whsec_` from base64, compute HMAC-SHA256 over `${webhook-id}.${webhook-timestamp}.${rawBody}`, base64-encode it, and compare it in constant time with each `v1,` value. Reject timestamps more than five minutes from your clock.

## Process each event once

- **Answer quickly.** Return 2xx as soon as the event is stored, and do slow work afterwards. A request has 10 seconds; anything else (a non-2xx status, a redirect, a timeout) counts as a failure.
- **Expect retries.** A failed delivery is retried with growing delays of up to 10 minutes between attempts, for about half a day, before it is set aside for an operator to replay. A retry can also arrive after a success, so the same `eventId` may come more than once.
- **Deduplicate by `eventId`**, and apply a change only when its `aggregateVersion` is newer than the version you stored for that resource. Events for one resource can arrive out of order.
- **Treat a checkout as paid only after `payment.checkout.paid`** (or after reading the checkout by reference). A browser redirect to your success URL does not prove payment.

## Event types

| Event | When | `data` |
| :--- | :--- | :--- |
| `payment.checkout.paid` | A checkout was paid. | `status: "paid"`, `checkoutId`, `paymentId`, `amount`, `currency` |
| `payment.intent.paid` | A payment intent was paid, for example a [GCash or Maya intent](/guides/payments/intents). | `status: "succeeded"`, `paymentIntentId`, `paymentId`, `amount`, `currency` |
| `payment.intent.failed` | The customer's attempt on an intent did not go through. To let them retry, create a new intent with a new idempotency key. | `status: "failed"`, `paymentIntentId`, `paymentId`, `amount`, `currency`, `failureCode`, `failureMessage` |
| `payment.allocation.held` | A payee's share of a payment is held until you release it. See [payouts](/guides/payments/payouts). | `status: "held"`, `allocationId`, `payeeId`, `paymentId`, `amount`, `currency` |
| `payment.payout.paid` | A payout reached the payee. `referenceId` is the payee's `externalRef`. | `status: "paid"`, `payoutId`, `payeeId`, `net`, `fee`, `currency`, `trigger` |
| `payment.payout.failed` | A payout did not go through; the earnings return to the payee's balance. | `status: "failed"`, `payoutId`, `payeeId`, `net`, `fee`, `currency`, `trigger`, `failureCode` |
| `payee.onboarding.updated` | A payee's test wallet onboarding status changed. | `onboardingId`, `payeeId`, `status`, `attempts` |

Intent events have `aggregateType: "payment_intent"`. APICenter does not send an event when a checkout or intent expires or is abandoned; read it to see its current status.

Accept event types you don't handle with a 2xx, so that new types never block your endpoint. The SDK returns them as `eventType: "unrecognized"`.

### Choose event types

By default a webhook receives every payment event type, including types added later. To receive only some, open the webhook on the project's **Webhooks** page in Management and choose **Edit events**. A change takes effect within about 30 seconds. Choosing no types goes back to every type. The filter applies to signed webhooks only; a Google Cloud push destination receives every type.

## Send a test event

On the **Webhooks** page, or the application's **Webhook** tab, **Send test event** sends a `webhook.test` event to the endpoint; you can send one about every 10 seconds per webhook. It is always delivered, whatever event types you chose. It is signed and retried like a payment event and has the same envelope, with `aggregateType: "webhook_destination"` and `data.test: true`. The SDK's `verifyWebhook` verifies it and returns it as `eventType: "unrecognized"` with `type: "webhook.test"`. Acknowledge it with a 2xx.

The console's delivery history shows each attempt for the webhook: the status your endpoint returned, the latency, the attempt number and any error. History is kept for 30 days.

## Rotate the secret

A rotation issues a new secret and keeps signing with the old one for 24 hours, so each delivery carries both signatures. Deploy the new secret, and during the overlap you can pass both to `verifyWebhook` as an array. After 24 hours only the new secret signs.
