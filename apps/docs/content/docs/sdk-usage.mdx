title: "SDK integration"
description: "Install and configure the server-side @alpha-explora/apicenter-sdk for APICenter's capabilities and payments."
---

`@alpha-explora/apicenter-sdk` is the typed Node.js client for APICenter's capabilities and payments. It is published to restricted GitHub Packages and requires package read access.

## Install

Add this configuration to the consumer repository's `.npmrc`:

```ini
@alpha-explora:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${NODE_AUTH_TOKEN}
```

Set `NODE_AUTH_TOKEN` in your local environment or CI secret store to a GitHub token with package read access. Do not commit a token or paste it into source code. Install the current release:

```bash
npm install @alpha-explora/apicenter-sdk@3.1.0
```

## Configure a service

Ask an APICenter operator for an application key per environment. Keep it in a server-only environment or secret manager. Do not use `NEXT_PUBLIC_` variables or expose the key to a browser.

```ini
APICENTER_API_KEY=ak_test_...
```

Create the client in backend code:

```ts
import { ApiCenter } from '@alpha-explora/apicenter-sdk';

// Reads APICENTER_API_KEY; the key selects test or live.
const api = new ApiCenter();
```

The key's prefix (`ak_test_` or `ak_live_`) selects the environment and the key identifies your application; APICenter enforces the actions it was granted.

## Call a capability

Supply an idempotency key for sends and OTP mutations. Generate or persist the key for the business operation, then reuse it when retrying that same operation.

```ts
const result = await api.email.send(
  {
    to: 'person@example.com',
    subject: 'Welcome',
    text: 'Your account is ready.',
  },
  { idempotencyKey: order.emailRequestKey },
);
```

Available namespaces include `email`, `sms`, `otp`, `geo`, `auth.google`, and `payments`. Request and response types are re-exported from `@alpha-explora/apicenter-contracts`.

```ts
const challenge = await api.otp.send({ recipient: 'person@example.com', channel: 'email', purpose: 'login' });

const location = await api.geo.reverseGeocode({
  latitude: 14.5995,
  longitude: 120.9842,
});
```

## Payments

Payments use the same application key when the application holds the matching `payments:*` grants; there is no separate payment key.

```ts
const checkout = await api.payments.checkouts.create(
  {
    referenceId: 'order-123',
    amount: { amountMinor: 49900, currency: 'PHP' },
    successUrl: 'https://app.example.com/payments/success',
    cancelUrl: 'https://app.example.com/payments/cancel',
  },
  { idempotencyKey: 'checkout-create-order-123' },
);
```

Every write carries an idempotency key. The SDK generates one per call and reuses it when it retries network errors, timeouts, 408, 429 and 5xx responses. For a write tied to a business operation, such as one checkout per order, store your own key (16 to 255 characters) with the operation and pass it, so a retry after a restart cannot repeat the write. A write the provider has not finished returns `{ status: 'pending', resourceId }`; check with `isPending(result)`.

## Errors

Every failure is an `ApiCenterError` with the HTTP `status`, APICenter's `code`, `details` when present, and a `requestId` to quote to support. Subclasses name the kind of failure: `AuthenticationError`, `PermissionError`, `ValidationError`, `NotFoundError`, `IdempotencyError`, `RateLimitError` and `QuotaExceededError` (with `retryAfterSeconds`), `ServerError`, and `ConnectionError`.

```ts
import { PermissionError, QuotaExceededError } from '@alpha-explora/apicenter-sdk';

try {
  await api.sms.send({ to: '+639171234567', message: 'Your code is ready.' });
} catch (error) {
  if (error instanceof PermissionError) console.error('Ask for the sms:send grant', error.requestId);
  else if (error instanceof QuotaExceededError) console.error(`Budget used up; retry in ${error.retryAfterSeconds}s`);
  else throw error;
}
```

Use the key issued for each environment: `ak_test_…` in test deployments, `ak_live_…` in production. Never share a key between applications or environments.
