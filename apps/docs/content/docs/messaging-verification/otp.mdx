description: "Generate, verify, and check 6-digit One-Time Passwords over SMS and Email via @alpha-explora/apicenter-contracts."

The OTP Shared Service manages the generation, anti-brute-force rate-limiting, and verification of one-time passcodes over SMS and Email.

For a Node.js backend, use `api.otp.send(...)` and `api.otp.verify(...)` from the [APICenter SDK](/guides/sdk-usage). The SDK sends an idempotency key with both writes; pass your own to tie a retry to the same sign-in attempt.

---

## Service Specifications

- **Base Route**: `/api/v1/shared/otp`
- **Required Header**: `Authorization: Bearer <application key>` (`ak_test_…` or `ak_live_…`; see [Authentication](/guides/authentication))
- **Required Header**: `Idempotency-Key: <16–255 characters>`

---

Use a separate key for each `generate` or `verify` request. Reusing the same key and body replays its original status and response for seven days. A changed body returns `409 IDEMPOTENCY_KEY_PAYLOAD_MISMATCH`; a concurrent request returns `409 IDEMPOTENCY_KEY_IN_PROGRESS`. If OTP delivery or verification has an uncertain outcome, APICenter returns `409 IDEMPOTENCY_OUTCOME_UNKNOWN` on retry and keeps the key blocked for reconciliation.

## 1. Generate OTP

- **Endpoint**: `POST /api/v1/shared/otp/generate`

### Request Body (`OtpGenerateRequest`)

```json
{
  "recipient": "+639171234567",
  "channel": "sms",
  "digits": 6,
  "ttlSeconds": 300
}
```

### Response (`OtpGenerateResponse`) — `201 Created`

```json
{
  "success": true,
  "data": {
    "otpId": "otp_9918231a48f29d10a9f",
    "expiresAt": "2026-07-31T23:25:00.000Z",
    "channel": "sms",
    "recipient": "+639171234567",
    "target": "+639171234567"
  }
}
```

---

## Test environment

With a test key (`ak_test_`), APICenter delivers only to the phone numbers and email addresses your project registers under **Settings** → **Test recipients** in Management. A send to anyone else still succeeds and is recorded, so your integration behaves the same, but nothing is sent. Those responses carry the header `X-APICenter-Test-Delivery: suppressed`. For those, the response also returns the generated `code`, so automated tests can verify it without receiving a message. Live keys deliver to everyone.

## 2. Verify OTP

- **Endpoint**: `POST /api/v1/shared/otp/verify`

### Request Body (`OtpVerifyRequest`)

```json
{
  "otpId": "otp_9918231a48f29d10a9f",
  "code": "849201"
}
```

### Response (`OtpVerifyResponse`) — `200 OK`

```json
{
  "success": true,
  "data": {
    "verified": true,
    "otpId": "otp_9918231a48f29d10a9f",
    "target": "+639171234567",
    "channel": "sms"
  }
}
```

### Verification errors

| Status and code | Meaning |
| :--- | :--- |
| `400 OTP_INVALID` | The code is wrong, or `recipient` does not match. |
| `400 OTP_EXPIRED` | The code has expired. Generate a new one. |
| `400 OTP_ALREADY_USED` | The code was already verified. |
| `400 OTP_ATTEMPTS_EXCEEDED` | The project's limit of wrong attempts was reached, so the code no longer works, even if correct. Generate a new one. |
| `404 OTP_NOT_FOUND` | No OTP with this `otpId` exists for your project and environment. |
| `429 RATE_LIMITED` | Too many verification attempts for this OTP in a short time. |

A code accepts five wrong attempts unless the project sets a different limit (1 to 10) in its OTP settings.

## Project settings

Each environment can have its own OTP settings, set in Management (**Capabilities** → OTP → **Configure**). Developers can change them in test; live needs a project admin.

| Setting | Range | Default |
| :--- | :--- | :--- |
| Code length | 4–10 digits | 6 |
| Expiry | 60–3600 seconds | 300 |
| Maximum wrong attempts | 1–10 | No limit beyond the verification rate limit |
| Message text | One line, up to 300 characters | `Your {{project}} verification code is {{code}}` |

`digits` and `ttlSeconds` in a generate request override the code length and expiry. The maximum attempts and the message text always apply; a change affects codes generated after it.

The message text must contain `{{code}}`. It may use `{{minutes}}` for the expiry in minutes and `{{project}}` for the project's name. Because it is sent from APICenter's own SMS and email senders, it cannot contain links, web addresses or phone numbers, and only a project admin can change it, in test as well.

Email OTPs carry the project's name: the sender shows as the project (for example `Serbizio <noreply@…>`), the subject is "Your Serbizio verification code", and the email shows the message text, the code, its expiry and a line saying APICenter sent it. A project name that contains a link, web or email address, or phone number is replaced with "APICenter" in messages.

## 3. Get OTP Status

- **Endpoint**: `GET /api/v1/shared/otp/status/:otpId`

### Response — `200 OK`

```json
{
  "success": true,
  "data": {
    "otpId": "otp_9918231a48f29d10a9f",
    "status": "pending",
    "target": "+639171234567",
    "channel": "sms",
    "expiresAt": "2026-07-31T23:25:00.000Z"
  }
}
```
