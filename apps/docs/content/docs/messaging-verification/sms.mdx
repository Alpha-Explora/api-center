---
title: "SMS"
description: "Send transactional text messages and track their delivery."
---

Send transactional text messages from your backend without integrating a telecom provider. Teams provide the message content in each request; APICenter does not store SMS templates.

For a Node.js backend, the typed client is `api.sms.send(...)` in the [APICenter SDK](/guides/sdk-usage). The REST reference below documents the same API for other runtimes.

---

## At a glance

- **Base Route**: `/api/v1/shared/sms`
- **Required Header**: `Authorization: Bearer <application key>` (`ak_test_…` or `ak_live_…`; see [Authentication](/guides/authentication))
- **Required Header**: `Idempotency-Key: <16–255 characters>`

---

## 1. Send Single SMS

- **Endpoint**: `POST /api/v1/shared/sms/send`

### Request Body (`SmsSendRequest`)

```json
{
  "to": "+639171234567",
  "message": "Your order #ORDER-991204 has been dispatched!"
}
```

### Response (`SmsSendResponse`) — `201 Created`

```json
{
  "success": true,
  "data": {
    "messageId": "msg_9918231a48f29d10a9f",
    "status": "sent",
    "to": "+639171234567",
    "sentAt": "2026-07-31T23:20:00.000Z",
    "recipient": "+639171234567"
  }
}
```

---

### Sender ID

`senderId` is optional. A project can pin a sender ID for each environment in Management (**Capabilities** → SMS → Configure): an E.164 phone number or an alphanumeric ID of up to 11 letters, digits or spaces. Once a sender is pinned, every message from that environment uses it. Leave `senderId` out or send the pinned value; any other value returns `403 SENDER_NOT_APPROVED` and nothing is sent. Without a pinned sender, messages use APICenter's default sender, and a `senderId` other than that sender is refused the same way: ask an APICenter operator to pin your sender ID.

Retries with the same key and request body replay the original status and response for seven days. Reusing a key with a different body returns `409 IDEMPOTENCY_KEY_PAYLOAD_MISMATCH`. If delivery has an uncertain outcome, APICenter blocks the key for reconciliation instead of sending again.

## Test environment

With a test key (`ak_test_`), APICenter delivers only to the phone numbers and email addresses your project registers under **Settings** → **Test recipients** in Management. A send to anyone else still succeeds and is recorded, so your integration behaves the same, but nothing is sent. Those responses carry the header `X-APICenter-Test-Delivery: suppressed`. Live keys deliver to everyone.

## 2. Get SMS Message Status

- **Endpoint**: `GET /api/v1/shared/sms/status/:messageId`

### Response — `200 OK`

```json
{
  "success": true,
  "data": {
    "messageId": "msg_9918231a48f29d10a9f",
    "to": "+639171234567",
    "message": "Your order #ORDER-991204 has been dispatched!",
    "status": "sent",
    "createdAt": "2026-07-31T23:20:00.000Z"
  }
}
```

---
Requests containing the obsolete `templateId` field return `400`. Send the message content in `message` instead.
