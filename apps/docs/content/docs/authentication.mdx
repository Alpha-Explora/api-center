# Authentication & Scopes

APICenter uses standard **OAuth 2.0 Client Credentials** and **JSON Web Tokens (JWT)** signed via RS256 algorithm.

---

## Auth Modes

APICenter supports three runtime authentication providers, configured via `AUTH_PROVIDER`:

1. **`dev-jwt` (Local Dev & CI)**: Self-contained RS256 issuer using ephemeral or local PEM key pairs. No external IdP dependency.
2. **`internal-jwt`**: Production machine-to-machine JWT issuer backed by GCP Secret Manager tribe secrets.
3. **`composite` (Production Default)**: APICenter issues internal tribe M2M tokens directly while validating Descope tokens for human/admin console sessions.

---

## Obtaining Machine-to-Machine Tokens

Send a `POST` request to `/api/v1/auth/token`:

```bash
curl -X POST https://api-center.itsandbox.site/api/v1/auth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "client_credentials",
    "client_id": "logistics-service",
    "client_secret": "sec_live_9481a7b...",
    "environment": "live"
  }'
```

### Response Payload

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIs...",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "payments:read payments:write sms:send email:send geo:read"
}
```

## Required Scopes Per Service

Each shared service route enforces fine-grained scope authorization:

| Shared Service | Route Pattern | Required Scopes |
| :--- | :--- | :--- |
| **Payments Write** | `/api/v1/payments/*` (POST, PUT, DELETE) | `payments:write` |
| **Payments Read** | `/api/v1/payments/*` (GET) | `payments:read` |
| **SMS Service** | `/api/v1/shared/sms/*` | `sms:send` |
| **Email Service** | `/api/v1/shared/email/*` | `email:send` |
| **OTP Service** | `/api/v1/shared/otp/*` | `otp:generate`, `otp:verify` |
| **Geo Location** | `/api/v1/shared/geo/*` | `geo:read` |

---

## Public JWKS Verification Endpoint

Consumer services can verify JWT signature authenticity using APICenter's public JWKS endpoint:

```text
GET /api/v1/auth/.well-known/jwks.json
```
