---
title: "Moving from direct PayMongo"
description: "Move a direct PayMongo integration onto APICenter."
---

Move provider access behind APICenter without changing your application’s domain references or customer return flow.

## 1. Replace the boundary

In Management, add an application for the backend, grant it the payment actions it calls and issue it a key; then replace direct PayMongo calls with the APICenter SDK or the documented `/api/v1/payments/*` routes. Keep your existing `referenceId`, order IDs, and success/cancel URLs. For TypeScript, the SDK exposes methods such as `api.payments.checkouts.create(...)` and `api.payments.intents.create(...)`.

## 2. Move credentials

Store the application's `APICENTER_API_KEY` in the backend's secret manager; the key alone selects the environment. After APICenter traffic has been verified, remove the consumer's direct PayMongo credentials. Provider credentials belong to the APICenter payment runtime.

## 3. Make events authoritative

A redirect or synchronous provider response is not a final business decision. Project payment state from `payment.checkout.paid`, `payment.checkout.failed`, refund, and subscription events. Store the event ID and aggregate version for duplicate suppression and ordering checks.

## 4. Cut over deliberately

Run test traffic first and compare normalized resources and event projections. Then enable the APICenter adapter behind the service's rollout flag. Coordinate the live cutover and direct-provider secret removal with the APICenter platform team.
