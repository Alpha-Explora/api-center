title: "Service registry and health"
description: "Register services through Management and use the APICenter gateway health probes."
---

Service registrations are created and maintained in **Management → Registry**. A service does not self-register at startup. The registry entry associates a service with a project, environment URL, exposed routes, required scopes, and allowed shared-service dependencies.

Follow [Register a service](/guides/management/register-service) to create a tribe, project, and service. The service's registered environment URL must be reachable by APICenter. The health path on the service manifest is the path APICenter can use to check that backend.

## APICenter gateway health

Use these endpoints to check the gateway process and readiness:

- **Liveness:** `GET /api/v1/health/live`
- **Readiness:** `GET /api/v1/health/ready`

Liveness reports whether the process is running. Readiness checks whether the gateway is ready to serve traffic. These gateway probes are separate from the health path registered for an individual service.
